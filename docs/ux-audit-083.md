## 怎麼走的

* 每個流程都開一個自己的 `--dev --test-offscreen --test-no-network --demo-branding` 執行個體（資料夾 `%LOCALAPPDATA%\PhoneMirror-dev-uxaudit`，TEMP 在工作資料夾），用 DevCommand 操作、`PrintWindow` / DevCommand 9xx 截圖。
  視窗位置每次啟動後、結束前都對所有螢幕檢查過（全部在 x = -6942，不在任何螢幕上）。
* 假來源：`--test-feed`（自己做的假手機畫面「Weekend Market」，720×1560 H.264）、`--test-source android`（假 Galaxy S24，點擊只記錄不送出）、`--test-source miracast`（程式產生的圖）。
* 遠端：`PM_REMOTE_LOOPBACK=1`（只開 127.0.0.2/127.0.0.3，沒有區網或 Tailscale listener，不會跳防火牆提示）、`PM_REMOTE_DRYRUN=1`（手機的操作只記錄）、`PM_REMOTE_FUNNELFAKE` / `PM_REMOTE_TUNNELFAKE`（假的固定網址和臨時網址，tailscale 和 cloudflared 都沒有執行）。
  手機頁用 Chrome headless（自己的設定檔，只連 127.0.0.x）。電腦端的「允許」一律按**拒絕**，所以真實桌面從沒有送出去。

* 兩種人：**長輩**＝第一次用、只會點看得到的大按鈕、不懂「網址／Wi-Fi Direct／偵錯」；**朋友**＝第一次在自己電腦設定遠端、會照著做但不知道 Tailscale 後台。

## 沒有驗證到的部分

* 真的 Tailscale / cloudflared（規定不能執行）：D1 的實際錯誤字串、啟用網址的樣子、D2 的等待時間都是依 owner 回報和官方文件，沒有實測。
* Tailscale 文件寫「only `http://127.0.0.1` is currently supported for proxies」（kb/1311），但自在投影用的是 `http://127.0.0.2:<port>`，owner 實際在用也正常；文件和實際不一致，沒有實測。
* 真的 iPhone / Android / Miracast、真的 adb、USB、配對逾時（B6）。
* 手機頁連上以後的畫面（要按允許才看得到，會送出真實桌面，所以沒做）；手機頁的設定頁是把 `remote/web/index.html` 用 file:// 打開、配假畫面截的。
* 輸錯密碼、鎖 15 分鐘的手機頁畫面（自動填密碼沒有送出）。
* 高 DPI、小螢幕、深色以外的主題。
